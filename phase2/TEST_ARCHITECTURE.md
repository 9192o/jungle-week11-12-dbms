# Phase 2 테스트 명세

대상 설계는 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다. 파서와 트리는 단위 테스트로 검증한다. 파일 내용과 실행 결과가 함께 맞아야 하는 동작은 임시 CSV와 실제 CLI에서 검증한다. Phase 1의 문장 경계·타입·CSV 저장·CLI 오류 처리 회귀 사례에는 Phase 2의 INSERT 문법과 정수 범위를 적용한다.

`phase2` 디렉터리에서 `python -B -m unittest discover -s tests -v`로 회귀 테스트를 실행한다.

| 경계 | 입력 또는 상황 | 확인할 결과 |
| --- | --- | --- |
| 트리 단위·속성 | 빈 트리, 정렬·역순·고정 seed로 섞은 키, 중복·미등록 키 | 검색 결과가 `dict[int, int]`와 일치한다. 중복 삽입은 기존 값을 바꾸지 않는다. 실패한 seed와 입력을 기록한다. |
| 분할 | 최대 키 3개로 리프와 내부 노드를 분할하고 루트 높이를 증가시킨다. | 모든 키와 오프셋이 조회된다. 구분 키와 같은 키는 오른쪽에서 찾는다. 내부 분할에서 `키 개수 // 2` 위치의 키를 올린다. 키 순서, 구분 키와 자식 범위, 자식 수, 리프 깊이가 규칙에 맞는다. |
| 바이트 오프셋 | LF, 한글·쉼표가 있는 선행 행, 마지막 LF가 없는 CSV, LF 없이 헤더만 있는 CSV | 원본 바이트에서 계산한 시작 위치와 인덱스 오프셋이 일치한다. 마지막 레코드 또는 헤더에 LF가 없으면 INSERT 후 새 행은 `이전 EOF + 1`에서 시작한다. CRLF CSV는 구축 오류로 처리한다. |
| 자동 ID | 빈 테이블, 여러 테이블, 기존 키 순서가 섞인 테이블, 큰 키가 있는 기존 CSV | 빈 테이블은 1부터 시작하며 테이블별 최대 키 다음 번호를 부여한다. 명시적 `record_id`, 열 목록 생략, 유효하지 않은 값은 거부하며 다음 자동 번호에 영향을 주지 않는다. |
| 범위 | 0, `2^64 - 1`, 음수, `2^64`를 SQL과 CSV에서 검증한다. 기존 최대 키가 `2^64 - 1`인 테이블에 INSERT한다. | 범위 양 끝을 정수로 처리하고 범위 밖 값은 거부한다. 다음 ID를 발급할 수 없으면 CSV와 인덱스가 그대로다. |
| 조회 경로와 결과 | ID 적중·미등록, 다른 열 조건, 조건 없음, 잘못된 위치 또는 다른 키로 읽히는 테스트용 오프셋 | ID 조건은 트리를 호출하고 적중할 때만 오프셋에서 한 줄을 읽는다. 다른 열 조건과 전체 조회는 순차 읽기를 쓴다. 인덱스와 강제 순차의 열·행이 일치한다. 오프셋의 행을 확인할 수 없거나 키가 다르면 저장소 오류다. |
| 시작·재시작 | 정상 CSV, 중복 키나 손상된 CSV, 종료 전에 추가한 행 | 정상 테이블을 재구축하고 재시작 후 저장한 행과 다음 자동 ID가 맞다. 구축 오류는 테이블명과 원인을 표준에러에 쓰고 문장 순번을 붙이지 않는다. 오류가 난 테이블만 차단하고 정상 테이블의 문장은 계속 실행하며 CLI는 1로 종료한다. |
| 실패 주입 | 부분 쓰기, `flush` 오류, 트리 등록 실패, 복원 또는 재구축 실패 | 복원 가능하면 CSV 바이트·트리 검색 결과·최대 ID가 실패 전과 같다. 복원할 수 없으면 해당 테이블의 읽기와 쓰기를 거부한다. |

## 성능 측정

`phase2` 디렉터리에서 `python -B benchmarks/lookup.py`를 실행한다. 데이터와 SQL은 임시 디렉터리에 생성한다.

1. 고정 seed로 데이터와 INSERT SQL을 생성해 100만 건 이상을 넣고 행 수를 확인한다. 데이터 준비 시간과 삽입 시간은 조회와 별도로 기록한다.
2. 동일한 CSV를 대상으로 인덱스 구축 시간을 기록한다. 구축 완료 후 파일 앞·중간·끝에 있는 `record_id`와 존재하지 않는 키를 조회한다.
3. 동일한 ID 조건을 인덱스와 테스트 전용 강제 순차 경로로 실행하고, 적중과 미등록 결과의 열·행이 일치하는지 확인한다. 다른 열의 순차 조회는 적중 여부와 결과 행 수를 비슷하게 맞춰 따로 잰다.
4. 조회 시간은 파일 읽기와 UTF-8 디코딩을 포함하고 결과 출력은 별도로 잰다. 같은 조건에서 반복해 중앙값, 반복 횟수, 데이터 건수, 파일 크기, 실행 환경과 캐시 조건을 기록한다.
5. 일반 회귀 테스트는 작은 CSV로 실행한다. 100만 건 성능 측정은 별도로 실행하며 특정 속도 배율을 합격 조건으로 두지 않는다.

격리된 테스트 작업에서 중복 검사 또는 오프셋 계산을 한시적으로 틀리게 바꾸고, 대응 회귀 테스트가 실패하는지 확인한다.
