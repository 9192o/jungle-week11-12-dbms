진행에 따른 평균 지연

요청을 60개 구간으로 나눈 구간별 평균입니다. 캐시가 채워질수록 mini-Redis를 거치는 쪽이 빨라집니다.

mini-Redis 캐시 적중률 (구간별)

측정 방법

  • 작업 — full-replay.csv의 앞에서부터 고른 수만큼, 클라이언트 하나가 응답을 받은 뒤 다음 요청을 보냅니다. 지연은 요청 한 건의 왕복 시간입니다.
  • 파일시스템 — 요청마다 articles.csv를 새로 열어 첫 줄부터 읽다가 id가 같은 줄에서 멈춥니다. 한 건에 수십 ms라 전체 요청 중 고르게 뽑은 표본만 실제로 재고, 총 소요 시간은 평균 × 요청 수로 추정합니다.
  • mini-DBMS — 별도 프로세스의 API 서버에 SELECT title FROM articles WHERE id = N;을 keep-alive HTTP로 보냅니다. 지연에는 HTTP·JSON 왕복이 들어 있습니다.
  • MySQL — 이 페이지 전용 데이터 폴더로 띄운 MySQL에 아래 쿼리를 보냅니다. pageviews에는 article_id 인덱스만 있어서 조회 시각의 최소·최대를 구하려면 그 문서의 조회 기록 행을 모두 읽습니다. 버퍼 풀은 1GB로, 두 테이블이 모두 메모리에 올라옵니다. 
    SELECT a.title, COUNT(*), MIN(p.viewed_at), MAX(p.viewed_at)
FROM articles a JOIN pageviews p ON p.article_id = a.id
WHERE a.id = ? GROUP BY a.id, a.title
  • MySQL + mini-Redis — mini-Redis에 GET stats:N을 먼저 보내고, 없을 때만 위 쿼리를 실행한 뒤 결과를 JSON으로 SET … EX 수명에 넣습니다. 적중하면 EXPIRE stats:N 수명을 보내 수명을 새로 줍니다. 적중은 왕복 2번(수명이 0이면 1번), 미스는 3번입니다. mini-Redis는 메모리 한도 없이 띄웁니다.
  • 캐시 수명 — 위에서 정한 수명(실제 경과 시간, 기본 60초)은 마지막으로 요청된 시점부터 셉니다. 계속 요청되는 문서는 남고, 수명 동안 한 번도 요청되지 않은 문서만 만료됩니다. 0으로 두면 만료 없이 넣습니다. 미스는 처음 요청된 문서와 수명이 끝난 문서로 나눠 셉니다.
  • 인기·비인기 구분 — 전체 조회 기록에서 요청 수가 많은 문서부터 더해 요청의 80%에 닿는 지점의 요청 수를 경계로 삼습니다. 측정하는 요청 수와 무관하게 전체 기록 기준으로 한 번 정합니다.
  • 결과 대조 — 고르게 뽑은 위치에서 얻은 답을 같은 비교의 두 방식끼리 맞춰 봅니다.
  • 조건 — 모든 프로세스가 이 컴퓨터 한 대에서 돕니다. 파일은 OS 파일 캐시에, MySQL 데이터는 버퍼 풀에 올라와 있어 어느 방식도 디스크를 읽지 않습니다. 비교 1과 비교 2는 조회 내용도 클라이언트도 달라서 서로의 수치를 직접 비교하지 않습니다.
