# Phase 1. SQL, CLI, CSV Storage

## 범위

CLI가 SQL 문장을 하나씩 읽고 파싱한 뒤 CSV 테이블에 실행한다. 지원 범위는 단일 테이블의 INSERT, SELECT, 선택적인 WHERE 동등 비교다. 테이블과 스키마는 미리 준비되어 있다고 전제한다.

## SQL 계약

> **SQL문을 읽고 해석하여 처리한다.**

| 입력 | 동작 |
| --- | --- |
| `INSERT INTO t VALUES (...);` | Phase 1에서는 `record_id`를 포함한 모든 열의 값을 스키마 순서대로 받는다. |
| `INSERT INTO t (col, ...) VALUES (...);` | 열과 값의 개수가 일치해야 한다. Phase 1에서는 `record_id`를 포함한 모든 열을 한 번씩 지정한다. 중복·미등록 열을 거부하고, 값은 스키마 순서로 재배치한다. |
| `SELECT * FROM t;` / `SELECT col, ... FROM t;` | 전체 열은 스키마 순서로, 명시된 열은 요청 순서로 반환한다. 결과가 없으면 열 목록과 빈 행 목록을 반환한다. |
| `WHERE col = literal` | 조건이 없으면 모든 행을 읽는다. 조건이 있으면 스키마에 등록된 열의 값을 해당 타입으로 비교한다. |

- Phase 2부터 `record_id`를 생략할 수 있다. 생략하면 자동 부여한다.
- 키워드, 테이블명, 열 이름은 대소문자를 구분하지 않는다. `SELECT`의 출력 헤더에는 스키마의 열 이름 표기를 그대로 사용한다. 문자열 값 비교에는 저장된 값을 그대로 사용한다.
    - 식별자는 영문, 숫자, 밑줄만 허용하며 첫 글자는 영문 또는 밑줄이다.
- 정수와 작은따옴표로 감싼 문자열을 구분한다. 부호 있는 10진 정수를 지원한다. 문자열 안의 작은따옴표는 두 개(`''`)로 표기한다. 예를 들어 `'O''Brien, 민;수'`는 문자열 값 하나다.
    - 토큰 사이에는 공백과 줄바꿈을 허용한다. 값 내부의 CR/LF는 거부한다.
- `INSERT` 값과 `WHERE` 조건값의 타입은 해당 열의 타입과 일치해야 한다. 정수 열에 문자열 `'1'`을 넣거나 비교하면 문장 오류로 처리한다. Phase 1은 `NULL`을 지원하지 않는다.
- SQL 문장은 세미콜론(`;`)으로 끝나야 한다. 파서는 한 문장의 입력을 끝까지 소비한다. 지원하지 않는 절이나 여분의 토큰은 구문 오류로 처리한다.
    - 공백만 있는 구간과 빈 문장은 문장 순번에서 제외한다.

## CLI 입력

> CLI는 Phase 1과 Phase 2에서 입력과 실행을 제어한다. Phase 3에서는 API가 이 역할을 맡는다.

- 명령줄 인자로 SQL 파일 경로를 받는다. `./query.sql`은 예시이며, 상대 경로는 CLI 실행 디렉터리를 기준으로 해석한다.
- SQL 파일을 UTF-8로 연다. 파일이 없거나 읽을 수 없으면 파일 오류를 보고한다.
- CLI는 `phase1` 디렉터리에서 실행한다. Phase 1의 테이블 디렉터리는 CLI 실행 디렉터리 기준 `./tables`다. 카탈로그에 `users` 테이블을 `users.csv`로 명시적으로 등록한다. SQL 파일 위치와 테이블 디렉터리 설정은 독립적이다.
    - 등록된 CSV 파일이 없으면 해당 문장을 실패 처리하고 다음 문장을 실행한다.
- 파서는 SQL을 한 문장씩 파싱해 실행기에 넘긴다. 경계를 찾을 수 있는 문장에서 구문 오류나 실행 오류가 발생하면 오류를 기록하고 다음 문장을 처리한다.
    - 문자열 내부의 세미콜론은 문장 경계로 해석하지 않는다. 작은따옴표가 파일 끝까지 닫히지 않으면 남은 구간을 한 문장의 오류로 보고한다.
    - 앞서 성공한 문장의 변경은 이후 문장이 실패해도 남는다.
- 성공한 `SELECT`마다 헤더와 행을 CSV 형식으로 표준출력에 쓴다. 일치하는 행이 없으면 헤더만 쓴다. 오류는 표준에러에 쓴다.
- 모든 문장이 성공하면 종료 코드 `0`을 반환한다. SQL 입력 파일 오류 또는 문장 하나 이상이 실패하면 `1`을 반환한다.

## CSV 저장소

- 카탈로그에 등록된 테이블명으로만 경로를 조회하고 기존 CSV 파일을 연다. 링크를 해소한 CSV 경로가 테이블 디렉터리 내부인지 확인한다.
- **첫 줄은 스키마**이며, 이후에는 **물리적 한 줄에 레코드 하나**를 둔다.
    - 헤더 예시는 `record_id:int,name:string,seat:int`이며, `:` 양옆에 공백을 허용한다.
    - 각 열은 `int` 또는 `string` 타입을 명시한다. `record_id`는 내부 식별·검색과 자동 번호 계산에 사용하는 정수형 기본키다. 추후 추가할 사용자 ID 열은 `user_id`로 명명한다.
- Python 표준 라이브러리 `csv`로 쉼표와 큰따옴표를 처리한다. 인용된 필드 안의 큰따옴표는 `""`로 표기한다. 예를 들어 `"민""수"`는 `민"수`로 읽는다.
- 읽기와 쓰기에 UTF-8과 LF 개행을 사용한다. 필드 내부의 CR/LF는 거부한다. 마지막 줄에 구분 개행이 없으면 레코드를 추가하기 전에 LF를 넣는다.
- 중복 헤더 이름, 지원하지 않는 타입, 잘못된 인용이나 인코딩, 행의 열 개수 또는 타입 불일치, 중복 `record_id`는 **저장소 오류**로 처리한다.
    - 대소문자만 다른 헤더 이름은 중복으로 처리한다.
    - 인용이 닫히지 않은 필드와 인용되지 않은 필드 안에 큰따옴표가 있는 경우는 저장소 오류다.
    - 빈 필드는 `string` 열에서만 허용한다.
- **복원에 실패하면** 현재 CLI 실행이 끝날 때까지 해당 테이블의 읽기와 쓰기를 차단한다. 다른 테이블의 문장은 계속 처리하고, 다음 실행에서 해당 파일을 다시 읽어 검증한다.

테스트용 CSV 예시는 [users.csv](../tables/users.csv)에 둔다.

## INSERT 실행 방식

1. 카탈로그에서 테이블을 찾고 열 이름, 값 개수와 타입을 확인한다. 열을 명시한 순서가 스키마와 다르면 값을 스키마 순서로 재배치한다.
2. 기존 CSV의 모든 행에 대해 열 개수와 모든 열의 타입을 확인하고, 기존 `record_id`의 중복을 검사한다. 오류가 있으면 파일을 변경하지 않고 문장을 실패 처리한다.
3. 파일에 쓰기 전에 `record_id`를 확정한다.
    - Phase 1에서는 명시한 `record_id`를 사용한다. 기존 레코드와 중복되면 파일을 변경하지 않고 실패 처리한다.
    - Phase 2에서도 명시값은 같은 방식으로 검증한다. 생략하면 기존 최댓값에 1을 더해 부여한다. 자동 부여값의 최솟값은 1이며, 빈 테이블의 첫 번호는 1이다.
4. 레코드 전체를 UTF-8 바이트로 변환한다. 구분 LF를 포함해 파일에 쓰기 전에 기존 EOF 위치를 기록한 뒤 파일 끝에 추가한다.
    - 짧은 쓰기 또는 `flush` 실패 시 기존 EOF 위치까지 복원하고 해당 문장의 실패를 보고한다. 복원을 확인할 수 없으면 CSV 저장소의 테이블 차단 규칙을 적용한다.

## SELECT 실행 방식

1. 요청한 출력 열과 조건 열이 스키마에 있는지 확인하고 조건값의 타입을 검사한다.
2. CSV를 순차적으로 읽는다. 출력하지 않는 열도 포함해 각 행의 모든 열을 검증한 뒤 `WHERE` 조건을 적용한다.
3. 검증 오류가 하나라도 있으면 해당 SELECT 전체를 실패 처리하고 헤더와 행을 출력하지 않는다.
4. 성공하면 요청 순서대로 출력 열을 골라 `Selected(columns, rows)`를 반환한다. `SELECT *`는 스키마 순서를 사용한다.

## 실행 예시

`students` 테이블의 스키마가 `record_id:int,name:string,seat:int`이고 `record_id` 3이 비어 있다고 가정한다. Phase 1에서 `INSERT INTO students (name, record_id, seat) VALUES ('영희', 3, 22);`를 실행하면 `3,영희,22`가 추가된다. 이어서 `SELECT name, seat FROM students WHERE record_id = 3;`를 실행하면 `name,seat` 헤더와 `영희,22` 행을 출력한다.
