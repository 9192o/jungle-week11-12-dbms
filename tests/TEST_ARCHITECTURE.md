# TEST_ARCHITECTURE.md

# Test Rules

- 요구사항마다 관찰 가능한 결과를 먼저 정한다.
- 파서와 B+ Tree는 단위 테스트로 빠르게 검증하고, SQL 실행 결과, CSV, 인덱스가 함께 맞아야 하는 동작은 실제 임시 파일과 CLI/API를 통해 확인한다.
- 테스트 대상 설계는 **ARCHITECTURE.md**를 따른다.
- 설계안으로 표시된 출력 형식과 오류 코드는 팀에서 채택한 뒤 계약 테스트로 고정한다.
- 실행 구성은 다음과 같다.
    
    
    | 종류 | 검증 경계 | 실행 시점 |
    | --- | --- | --- |
    | 단위 | 문장 경계, 파서, 스키마 검사, B+ Tree | 관련 기능 변경 시 |
    | 통합 | 실제 CSV와 실행기, CLI 파일 입출력, API 응답 | 기능 작업 완료 시 |
    | 시나리오 | 프로세스 재시작, 쓰기 실패, 요청 경합, 풀 포화 | 해당 Phase 회귀 검증 시 |
    | 속성 기반 | 입력 순서와 값이 달라져도 유지되는 결과·구조 불변식 | 파서, 저장소, 트리 변경 시 |
    | 성능 | 자동 생성한 100만 건 이상에서 인덱스와 선형 조회 비교 | Phase 2 완료 확인 및 성능 변경 시 |

# Phase 1. SQL 처리기

| 경계 | 입력 또는 상황 | 확인할 결과 |
| --- | --- | --- |
| 문장 경계, 파서 | 여러 줄, 혼합 대소문자, `'O''Brien, 민;수'` 뒤에 다음 문장 | 문자열 속 공백·쉼표·세미콜론이 보존된다. 작은따옴표는 하나로 해석한다. 다음 문장은 별개로 실행한다. |
| SQL 거부 | 닫히지 않은 문자열, 괄호 누락, 비교 연산자 `>`, 복합 조건, DDL·UPDATE·DELETE, 여분 토큰 | 구문 오류가 반환되고 해당 문장에서 파일이 바뀌지 않는다. 따옴표가 닫히지 않은 꼬리 구간은 한 건으로 보고한다. |
| INSERT | 위치 기반 값, 순서가 다른 명시 열 목록 | 같은 스키마 순서로 한 행이 추가된다. 헤더를 보존하고 한글·쉼표·큰따옴표가 읽기까지 왕복한다. |
| INSERT 검증 | 열·값 개수 불일치, 없는 열, 중복 열, 누락 열, 잘못된 타입, 중복 ID, 필드 내부 CR/LF | 각 입력에 오류를 반환하고 파일 바이트가 이전과 같다. 따옴표로 감싼 숫자와 정수 리터럴을 구분한다. |
| SELECT | 전체·열 선택·정수 조건·문자열 조건·조건 불일치·헤더만 있는 CSV | 열과 행의 결과 및 요청 열 순서가 맞다. 결과가 없으면 행이 비어 있다. 없는 출력 열이나 조건 열은 오류다. |
| 파일 오류 | 누락된 SQL 파일, 읽기 실패, 매핑에 없는 테이블, 잘못된 UTF-8·헤더·행 너비·CSV 인용 | 원인을 보고한다. 필요한 I/O 실패는 권한 설정에 의존하지 않고 주입한다. |
| 파일 경계 | 등록되지 않은 이름과 작업 디렉터리 밖으로 해석되는 등록 경로 | 오류를 반환하고 지정한 테이블 디렉터리 안의 등록 파일만 접근한다. 임시 디렉터리에 둔 외부 파일의 내용이 보존된다. |
| CLI 배치 | 성공 INSERT → 구문 오류 → 중복 INSERT → 성공 INSERT → SELECT | 결과와 오류가 stdout/stderr로 분리된다. 실패 문장의 순번과 원인이 보인다. 종료 상태는 실패이며 두 성공 행은 조회된다. 전부 성공하는 배치는 성공 상태로 끝난다. |
| 보존/실패 | CLI 프로세스를 종료하고 같은 디렉터리로 다시 실행, 행 추가 도중 일부 바이트 쓰기 후 실패 | 재실행에서 저장한 행을 읽는다. 복원 가능한 실패에서는 이전 CSV 바이트와 결과가 그대로다. |

# Phase 2. B+ Tree, 자동 ID, 바이트 오프셋

| 경계 | 입력 또는 상황 | 확인할 결과 |
| --- | --- | --- |
| 트리 단위 | 빈 트리, 첫 삽입, 오름차순·내림차순·섞인 ID, 중복·미등록 키 | 정확한 `id → offset`을 돌려준다. 중복 키를 거부하고 기존 값은 유지한다. |
| 분할 | 리프 및 내부 노드를 분할하고 루트 높이까지 증가시키는 입력 | 모든 키를 다시 찾는다. 노드 내 키 순서, 구분 키와 자식 범위, 자식 수, 동일한 리프 깊이를 검사한다. 구분 키와 같은 ID도 정확히 조회한다. |
| 오프셋 | LF·CRLF, 한글·쉼표가 있는 선행 행, 마지막 개행 없는 CSV에 삽입 | 원본 바이트에서 계산한 행 시작 위치와 인덱스가 일치한다. 해당 오프셋을 읽으면 정확한 한 행을 얻는다. |
| 자동 ID | 빈 테이블, 여러 테이블, 순서가 섞인 기존 ID, 큰 명시 ID 추가, 중복 명시 ID | 빈 테이블은 1부터 시작한다. 테이블별 현재 최대 ID + 1을 사용한다. 거부된 삽입은 다음 ID 계산에 영향을 주지 않는다. |
| 조회 경로 | ID 적중·실패, 다른 열 조건, 조건 없음 | ID는 B+ Tree를 호출하고, 적중했을 때만 오프셋 읽기를 수행한다. 기타 조건과 전체 조회는 순차 읽기를 사용한다. 호출 관찰과 실제 결과로 검증한다. |
| 결과 동등성 | 같은 ID 조건을 인덱스와 강제 선형 경로로 실행 | 적중과 미등록 모두 열과 행이 동일하다. |
| 시작·재시작 | 미리 준비된 CSV와 종료 전에 추가한 행, 잘못된 CSV 또는 중복 ID가 있는 CSV | 정상 파일의 인덱스를 다시 만든다. 잘못된 파일은 구축 오류를 보고한다. |
| 삽입 실패 | 부분 쓰기, flush 실패, 트리 갱신 도중 실패, 복원 또는 재구축 실패 | 복원 가능하면 CSV·인덱스·최대 ID가 이전 상태와 같다. 복원을 확인할 수 없으면 해당 테이블의 추가 읽기와 쓰기를 거부한다. |

# Phase 3. API와 동시성

| 경계 | 입력 또는 상황 | 확인할 결과 |
| --- | --- | --- |
| HTTP 요청과 응답 | 실제 로컬 서버에 POST로 INSERT, ID SELECT, 빈 결과 조회 | 삽입 ID와 구조화된 열·행을 반환한다. ID 조회의 트리 호출을 확인한다. 같은 SQL을 CLI에서도 실행해 결과 의미를 비교한다. |
| 입력 검증 | 잘못된 JSON, SQL 누락, 크기 경계와 초과, 다중 문장, 지원하지 않는 SQL, 등록되지 않은 테이블, 중복 ID | 응답 상태와 오류 구조가 계약에 맞고 실패 요청은 저장 상태를 바꾸지 않는다. 다중 문장은 첫 문장도 실행하지 않는다. |
| 동시 INSERT | 시작 장벽을 둔 여러 클라이언트가 같은 테이블에 자동 ID 삽입. 첫 삽입이 쓰기 락을 보유할 때 다른 삽입이 쓰기 락에서 대기하는지 확인한다. | 첫 락이 풀릴 때까지 다른 삽입은 ID 발급을 시작하지 않는다. 성공 응답 수만큼 유효한 CSV 행이 생기고, 성공 ID는 모두 다르며 인덱스에서 조회된다. |
| SELECT + SELECT | 첫 조회를 읽기 락을 얻은 뒤 멈추고, 여유 작업 스레드에서 같은 테이블의 두 번째 조회를 시작한다. 서로 다른 ID와 같은 ID를 각각 조회하고, 두 인덱스 조회의 `seek()`와 실제 읽기를 교차시킨다. | 첫 조회를 재개하기 전에 두 번째 조회가 완료된다. 두 요청 각각에서 기대한 행이 나오고 CSV는 유지된다. |
| SELECT + INSERT | 첫 조회가 읽기 락을 보유한 상태에서 같은 테이블의 삽입을 시작하고, 삽입이 쓰기 락 대기에 들어갔는지 확인한다. | 조회가 끝날 때까지 ID 발급, CSV 쓰기, 인덱스 갱신이 시작되지 않는다. 락 해제 후 삽입과 후속 조회가 성공한다. |
| INSERT + SELECT | 쓰기와 인덱스 갱신 사이에 삽입을 멈추고 같은 테이블 조회가 읽기 락을 기다리는지 확인한다. | 쓰기 락 해제 전에는 CSV나 인덱스를 읽지 않는다. 성공 뒤에는 완전한 행을 반환한다. 실패를 주입한 경우 유효한 복원 상태 또는 테이블 사용 불가 오류를 반환한다. |
| 대기 중인 쓰기 우선 | 첫 조회를 잡아 둔 상태에서 같은 테이블의 삽입을 쓰기 대기에 넣은 뒤, 여유 작업 스레드에서 새 조회를 시작한다. | 새 조회는 읽기 락을 기다린다. 첫 조회가 끝나면 삽입이 쓰기 락을 얻고, 삽입이 끝난 다음 새 조회가 실행된다. |
| 테이블 독립성 | A의 락을 잡은 작업을 중단 지점에 붙잡고, 여유 작업 스레드로 B를 호출 | A를 재개하기 전에 B가 완료된다. |
| 풀 포화 | 작업 스레드와 대기 슬롯을 채운 뒤 추가 요청, 수락 작업 완료 후 재요청 | 설정한 스레드 수를 넘지 않고 초과 요청은 정해진 상태로 거부된다. 완료 후 재접수와 작업 스레드 재사용을 확인한다. |
| 오류 후 상태 | 읽기 락 안과 쓰기 락 안에서 각각 실패를 주입한 뒤 같은 테이블과 다른 테이블에 요청한다. | 예외 뒤 해당 락과 작업 슬롯을 반환한다. 복원이 가능하면 후속 읽기와 쓰기가 진행되고, 복원에 실패한 테이블만 격리된다. |
| 서버 재시작 | 서버를 정상 종료한 뒤 동일 디렉터리로 새 프로세스를 띄움 | 기존 행을 ID로 조회하고 다음 자동 ID도 저장된 최댓값을 반영한다. 로컬 브라우저에서 API 호출도 확인한다. |

# 테스트 상세

### 속성 기반 테스트

- 고정 seed로 여러 삽입 순서를 생성한다.
    - 트리의 검색 결과를 `dict[int, int]`와 대조하고 각 삽입 뒤 구조 불변식을 확인한다.
    - 실패한 seed나 입력은 다시 실행할 수 있게 남긴다.
- 한글과 구분 문자가 섞인 한 줄 문자열을 SQL 리터럴로 만들어 파싱하고 CSV를 왕복한 값이 원본과 같은지 검사한다.
    - CR/LF가 포함된 값은 거부 케이스로 검사한다.
- 처음에는 표준 라이브러리 기반으로 반복 케이스를 만들 수 있다.
- 자동 축소가 필요해지면 속성 테스트 도구 도입을 검토한다.

### 성능 측정

1. seed가 고정된 데이터와 SQL 입력을 생성하고 100만 건 이상을 삽입한다. 행 수를 검증한다. 데이터 준비와 삽입 시간을 조회에서 빼고 별도로 기록한다.
2. 같은 CSV에서 인덱스를 재구축하는 시간을 측정한다. 조회는 구축이 끝난 뒤 시작한다. ID는 파일 앞,중간,끝에 있는 값과 없는 값을 사용한다.
3. 같은 ID 조건을 인덱스와 강제 선형 탐색으로 실행한다. 인덱스가 없는 다른 필드의 선형 탐색도 별도로 재고, 적중/실패와 출력 행 수를 비슷하게 맞춘다. 각 조건에서 기대한 결과를 비교한 뒤 시간을 기록한다.
4. 출력 없는 조회 시간과 결과 출력 시간을 구분한다. 동일한 조건에서 반복하고 중앙값, 반복 횟수, 데이터 건수, 파일 크기, 실행 환경과 캐시 조건을 기록한다. 파일 I/O와 디코딩을 포함한 조회인지 명시한다.
5. 일반 회귀 테스트는 작은 fixture에서 조회 결과와 경로를 검증한다. 100만 건 측정은 독립적으로 실행하며 특정 속도 배율을 합격 조건으로 두지 않는다.
- 동시성 테스트의 실행 순서는 장벽과 이벤트로 제어한다. 대기해야 하는 요청은 실제로 락 대기에 도달했는지 확인하고, 테스트에 필요한 동시 요청 수만큼 작업 스레드를 확보한다.
- 시간 제한은 테스트가 무한히 멈추는 것을 방지하는 데 쓴다.
- 단순히 잠깐 기다렸다가 결과가 맞는지 보는 방식으로 경합을 검증하지 않는다.

## 테스트가 실제 결함을 잡는지 확인

- 핵심 회귀 테스트를 골라 중복 검사, 바이트 오프셋, 테이블 락 중 하나를 임시로 잘못되게 바꿨을 때 대응 테스트가 실패하는지 확인한다.
- 격리된 테스트 작업에서만 실시한다.
